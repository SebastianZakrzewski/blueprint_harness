## Summary

Delivers **Milestone M0 — Monorepo scaffold** from `docs/exec-plans/active/build-harness-blueprint-v1.md`.

### M0 goal

Establish a minimal runnable pnpm + TypeScript monorepo whose package boundaries match `ARCHITECTURE.md`.

### M0 scope included

- pnpm workspace configuration (`pnpm-workspace.yaml`, `pnpm-lock.yaml`, `.npmrc`)
- Root toolchain config (`package.json`, `tsconfig.base.json`, `.nvmrc`, `.gitignore`, `vitest.config.ts`)
- Five package stubs with strict TypeScript build and Vitest smoke tests
- ExecPlan progress update marking M0 complete and active milestone set to M1

### M0 scope excluded (intentionally deferred)

- Harness CLI commands and `harness` binary (M6)
- Universal Core implementation: invariants, lifecycle, validation schemas (M1)
- Workspace dependency edges between packages (M1+)
- CI workflows (M12)
- Template rendering, profile SDK contracts, bootstrap logic

Pre-commit checks:

- Complete diff reviewed: M0 infrastructure + ExecPlan progress only
- No `dist/` or `node_modules/` tracked (confirmed via `git ls-files` and `.gitignore`)
- No `workspace:*` inter-package dependencies yet

## Known limitations

- `pnpm lint` is a stub (`echo lint stub`); real linting is deferred to later milestones.
- No CI workflow yet; local commands are the M0 gate.
- Package dependency graph from `ARCHITECTURE.md` is not wired yet (by design for M0).

## M1 not implemented

This PR does **not** implement M1 Universal Core behavior (invariants, lifecycle states, `ValidationResult`, ownership classes, policy interfaces, or checkpoint model). `packages/core` remains a placeholder stub.

## Rollback procedure

1. Revert merge commit on `main` (or close PR without merging).
2. Verify prior milestone validation: repository returns to docs-only baseline.
3. Safe to delete local `node_modules/` and `dist/` artifacts; they are gitignored.
